# Security Policy

## Automated security gates

No scanner is disabled and no threshold has been lowered. Every gate fails the pipeline.

| Gate | Tool | Fails when |
|---|---|---|
| Secret scanning | Gitleaks, full git history, `.gitleaks.toml` | any secret is found (the only allowlist entry is the seeded demo password `password123` used by tests) |
| Static analysis | SonarCloud | quality gate is not passed (`sonar.qualitygate.wait=true`) |
| Dependency scanning | Snyk (`--severity-threshold=high`) on backend and frontend | any high or critical vulnerability |
| Image scanning | Trivy, `HIGH,CRITICAL`, exit code 1 | any high or critical CVE in either image |
| Dockerfile lint | Hadolint (threshold: warning) | any finding |
| Script lint | ShellCheck | any finding |
| Automated updates | Dependabot (`.github/dependabot.yml`) for npm, Docker and GitHub Actions | weekly update pull requests |

## Secrets handling

* Nothing sensitive is committed. The JWT signing secret is generated by AWS Secrets Manager and read by instances at boot; the backend refuses to start in production without `JWT_SECRET`.
* CI tokens (`SONAR_TOKEN`, `SNYK_TOKEN`) live in GitHub Secrets.
* The pipeline uses GitHub OIDC to assume AWS roles. There are no long-lived AWS access keys.

## Cloud hardening

* Separate least-privilege IAM roles: EC2 instance role, CI role (ECR push only), deploy role (SSM parameters + ASG refresh only). GitHub roles trust only `repo:jabeen-zahra/SnapBrand:ref:refs/heads/main`.
* Instances live in private subnets with no public IP. Their security group accepts traffic only from the load balancer security group. SSH (port 22) is closed; administration uses SSM Session Manager.
* IMDSv2 required, encrypted EBS volumes, ECR tag immutability and scan-on-push.
* Containers run as non-root users (backend UID 10001, frontend nginx-unprivileged UID 101) on pinned base images.

## Known findings and exceptions

Every finding must be fixed or listed here with a reason. Trivy exceptions additionally go in `.trivyignore`.

| Component | Identifier | Severity | Reason and mitigation | Review date |
|---|---|---|---|---|
| Transport | Load balancer serves HTTP only (no TLS certificate/domain) | accepted risk | No domain is available for an ACM certificate in this academic deployment. The app carries no real user data. Mitigation: add an ACM certificate and an HTTPS listener with redirect when a domain exists. | 2026-11-25 |
| Storage | File-backed storage is per instance (not replicated) | design limitation | Keeps the project small. Data is demo data only. Mitigation: move to RDS/DynamoDB. | 2026-11-25 |
| Network | Single NAT gateway (one AZ) | availability trade-off | Cost control. Loss of that AZ interrupts only outbound access from private instances, not inbound serving of running instances. | 2026-11-25 |

(No open high or critical scanner findings are suppressed. Any future exception from Snyk or Trivy must be added to this table in the same pull request.)

## Reporting a vulnerability

Open a private GitHub Security Advisory on this repository or contact the maintainers listed in the README.
